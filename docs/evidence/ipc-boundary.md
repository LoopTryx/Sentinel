# IPC boundary evidence and next implementation gate

The `sentinel-svc` crate contains a deny-by-default method policy and a fixture-only local named pipe. It returns checked-in capability fixture data after verifying the connected client's token. It is not installed as a Windows service and does not authorize or perform policy mutations.

The fixture has distinct user and admin pipe names. Each sets an explicit DACL for the process token's logon-session SID and `PIPE_REJECT_REMOTE_CLIENTS`. Microsoft's [named pipe security guidance](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) says the default descriptor grants read access to Everyone and anonymous users. It also warns that generic write includes `FILE_CREATE_PIPE_INSTANCE`; the fixture DACL excludes that right, and a same-user second-server test observes access denied. The final service still needs installed and isolated endpoints.

After a client sends a request, the fixture pipe calls `ImpersonateNamedPipeClient`, reads SID, session, and elevation from the thread token, and calls `RevertToSelf`. Microsoft's [impersonation guidance](https://learn.microsoft.com/en-us/windows/win32/ipc/impersonating-a-named-pipe-client) describes that flow and notes that client impersonation level is client-controlled. Request-supplied SID fields are rejected. The admin fixture requires an elevated token for admin methods; it always returns unsupported after authorization. No policy method is implemented here.

Before enabling any policy method, integration tests must cover mismatched SID/session, low-integrity or non-elevated clients, remote connection attempts, client disconnects during impersonation, nonce replay, rate limits, read timeouts, and a service crash. Resource ownership checks remain necessary after method authorization. Current interactive local tests cover the same-user token path, oversized frames, forged identity fields, denied admin methods, denied second server instance, and logon SID extraction. CI may run in session 0 and skip interactive pipe assertions; a dedicated Windows interactive integration run is still required.
