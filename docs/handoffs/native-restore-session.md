# Native retained scan/quarantine/restore session

Authoritative source: `crates/sentinel-proto/src/restore_action.rs`; five restore bindings generated by proto export tests. Existing quarantine/selected-scan types remain authoritative. No destination, caller, clock or approval boolean in client requests.

## Functions and semantics

`SelectedJobs::prepare_restore(owner, &RestorePrepareRequest, now) -> Result<RestorePreview, QuarantineError>` binds a privately retained successful quarantine/removal receipt to the owner and a fresh30-second single-use reference. New valid previews supersede prior ones; foreign/malformed requests do not consume them. `restore_after_native_confirmation(owner, &RestoreActionReference, fresh_now, &Vault, native_confirmation) -> Result<RestoreReceipt, QuarantineError>` consumes the action before decline, revalidation or filesystem access. It checks authenticated recovery-journal digest/bytes/removal phase against private original scan evidence, then calls verified create-new/retained-ancestry restore to the original private destination only. Existing targets are preserved. Success retires the retained receipt; failure may leave durable recovery/partial target state, never retry automatically.

Owner/time/vault/confirmation derive from the trusted native host. Up to64 restorable receipts/controller; capacity refuses new approved quarantine before file mutation. Only quarantined, not original_retained, is eligible. Cancel/new selection revoke pending restore; fresh explicit preparation may still use a retained receipt. Original paths and digest/byte association stay private. Controller references are not authentication and are not reconstructed after restart; durable journal recovery/re-authorization is a separate native operation.

Request example: `{"quarantineActionRef":"action_1"}`; confirm/decline: `{"restoreRef":"restore_1"}`. Preview: `{"restoreRef":"restore_1","quarantine":{"actionRef":"action_1","selectionRef":"selection_1","jobRef":"job_1","reportRef":"report_0","vaultFile":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa.qtn","state":"quarantined"},"expiresAfterSeconds":30}`. Success has the same restoreRef/quarantine plus `state:"restored"`. Errors use closed QuarantineError; action_failed can require recovery.

## Private process protocol

`sentinel-inspect --file <native-selected-path> --session <native-private-app-directory>` (or --folder) retains actual SelectedJobs and vault state at most300 seconds. No listener/privilege or cross-user authentication. Process separation is not restricted-token/network-denied isolation.

Output envelopes: `{"type":"scan","data":ScanJobSnapshot}`, quarantine_preview/receipt, restore_preview/receipt, and `{"type":"error","data":QuarantineError}`. Scan evidence remains historical after disposition. Input: closed newline JSON, <=1024 bytes/frame, <=64 frames/session, queue4. Operations: cancel/close; prepare_quarantine {reportRef}; confirm_quarantine/decline_quarantine {actionRef}; prepare_restore {quarantineActionRef}; confirm_restore/decline_restore {restoreRef}. No path/approved fields. EOF/close cancels and waits for worker exit; malformed/oversized input closes with invalid_request. Parent must additionally bound/drain output and enforce shutdown/resources.

**Confirm commands may only be sent by the trusted native desktop parent after its own explicit OS dialog.** Never map them to browser methods or arbitrary renderer/network requests. The native window implementation is described below; visible UI consent acceptance remains unverified. The child cannot independently prove its parent showed a dialog: tests exercise the trusted-parent branch, not visible consent.

## Native parent adapter

### Native window confirmation routes

Bootstrap now includes a separate64-hex nativeActionToken retained by GlassConsole, never included in renderer/state/pair replies. Native disposition endpoints require the desktop bearer, no Origin, and X-Sentinel-Native-Action. Paths/executable/owner/approved fields are rejected. POST quarantine-prepare accepts {reportRef}; quarantine-confirm/decline accepts {actionRef}; restore-prepare accepts {actionRef}; restore-confirm/decline accepts {restoreRef}. Canonical envelopes include preview/receipt or closed error; missing service is503 unavailable. The native route chooses the decision internally; the browser cannot use these endpoints even with the action credential.

Glass renderer methods quarantine.request({reportRef}) and restore.request({actionRef}) invoke preparation, then a real default-No owned WPF MessageBox. The host derives the decision reference from the returned preview and sends confirm/decline only after that dialog result. It shows its private native selection/report and completed SHA256 for quarantine, and remembers the successful receipt's private selection label for restore. That label is display only; Rust owns the actual original destination. Concurrent dialogs and selection during a dialog are refused. Requests accept no renderer approval/destination. Expired/action failures are returned; no automatic retry. UI controls remain pending the shared editing handoff, so this compile does not establish a visible user journey.

Actual runtime tests exercise trusted native HTTP credentials on owned harmless C: data: browser/ordinary desktop refusal, injected approved rejection, decline preserving bytes, replay refusal, completed quarantine/removal and exact-byte original restore. These tests bypass the visual MessageBox and do not prove OS consent or visible renderer integration. Independent review remains required before main integration.

`native-action-service.mjs` provides an awaitable private service over the parent: ready resolves actual scan terminal evidence; prepare and native decision methods resolve canonical response envelopes. One pending action,5-second action deadline, close settles pending/scan waits, and missing process reports unavailable. The runtime retains this service when trusted bootstrap supplies nativeAppDir; cancel reaches it and replacing selection/shutdown waits for the prior owned child to close. CLI uses a separate LocalAppData/Sentinel-School-Demo/inspection-vault directory. The later native-window routes above connect it with separate credentials; service tests exercise the trusted branch only.

`apps/demo-runtime/native-session-parent.mjs` exports `openNativeSession({executable,path,kind,appDir,onMessage,timeoutMs})`. Only trusted native configuration may supply these inputs. The returned frozen capability exposes done, close, cancel, prepareQuarantine(reportRef), prepareRestore(quarantineActionRef), nativeQuarantineDecision(actionRef, approved), and nativeRestoreDecision(restoreRef, approved). Decision methods are exclusively for the trusted OS-dialog branch; do not route them through renderer, HTTP or extension requests. No visible dialog is wired by this module.

Responses pass the closed canonical envelope validator before callbacks. One action request may be outstanding; previews and receipts correlate to its report/action and retained job/selection. Restore requires an actually retained successful quarantine receipt and validates the returned nested receipt. Parent limits combined output to2MiB, each line to64KiB, commands to63 plus close, session to300 seconds, and graceful shutdown to1 second before killing its own child. It drains stderr without disclosing it, decodes UTF8 across chunk boundaries and resolves done only on child close. Missing engine is unavailable, deadline is timed_out, malformed output is failed. These states are not clean scan results. Actual harmless parent scan/quarantine/restore, missing-engine and deadline tests are in native-session-parent.test.mjs. This is process transport evidence, not installed desktop/browser acceptance.
