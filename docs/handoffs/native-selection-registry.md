# Native selection registry — issue 9

`sentinel_scan::selection::NativeSelectionRegistry` retains at most one private path. Native Rust callers create `new()`, then call `register_native_selection(path: PathBuf, kind: SelectionKind) -> Result<String, InvalidNativeSelection>` ONLY after their trusted picker approves that exact path. This function is not a picker, consent check, service authentication or remote path input endpoint. Never expose its path argument to JavaScript, browser messages or generic IPC.

Registration clears the previous entry even on failure. It requires an absolute path, no NUL and at most 32768 bytes in Rust's platform-specific OsStr encoding. It does no filesystem I/O, canonicalization or existence/type checking. Kind is the trusted picker's declared File/Directory intent; scanner validation remains authoritative. Process-global checked monotonically increasing references prevent reuse across registries in the running process; overflow returns fixed `invalid native selection` and leaves no entry. References are predictable correlation values, not secrets or bearer authorization, and are not valid across process restart.

`resolve(&self, reference: &str) -> Option<&ApprovedSelection>` accepts exactly the current reference. The approved object exposes `path() -> &Path` and `kind() -> SelectionKind` to native code only; neither registry nor entry supports serialization or cloning. Debug omits paths. `clear()` invalidates the retained entry. Rust borrows prevent replacement while an approved entry is borrowed; this is not a global concurrency or process-lifecycle gate. A native dispatcher may need a private path copy, but must then explicitly cancel/reap abandoned work and discard its late results using BOTH fresh job and selection references.

This stores picker intent, not a stable filesystem identity or read-only handle. Paths can change after selection. Existing scanner checks still apply, and stronger handle-based authority, bounded worker dispatch, hard deadline/kill/reap and actual Tauri picker commands remain pending. Do not enable scanAvailable or label an installed service from this library leaf.

The three checks cover replacement/clear/cross-registry rejection, failed-registration invalidation/path-free errors/debug, and an actual harmless selected file converted into a path-free report. Initial tests failed because the selection module did not exist (compile-time missing API, not a reproduced preexisting runtime bug). Full integration, GUI and event rehearsals are not claimed.
