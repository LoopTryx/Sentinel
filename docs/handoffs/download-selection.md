# Download observation contract — preparation only

Owner: Engineer A, issue14; coordinator editing assignment comment6087267307. Base main 93b990f. Engineer B reviews the contract/security boundary. This first slice enables no browser permission, RPC, filesystem access, download monitoring or inspection.

Authoritative source: sentinel-proto/src/download_selection.rs. TypeScript DownloadObservation is generated by the existing ts-rs export test, not a hand-written mirror.

Example: {"sessionRef":"session-1","downloadRef":"download-1"}.
Signature: DownloadObservation::validate(&self) -> Result<(), InvalidDownloadObservation>. Both references must contain 1–64 ASCII letters/digits/underscore/hyphen. Unknown JSON fields are rejected, including path, URL, credentials and raw content. Caller must validate after decoding and before retention; deserialization alone is not semantic validation. Fixed error carries no input. Authentication and browser completion observations are separate from this correlation. A browser cannot create native approval by supplying these references.

No UI operation or scan API is enabled. UI must keep download inspection unavailable. Observation does not prove that a file exists, is complete, was inspected or is safe. No progress, cancellation or timeout promise is implemented by this DTO.

Windows candidate still needs reparse ancestry, supported local-volume identity matrix, private staging ACL/exclusive/no-follow creation and crash cleanup evidence. Keep 8 MiB/file cap. Never feed existing path-based benign dispatcher an untrusted browser path. Platform/transport enabling waits for independent review.
