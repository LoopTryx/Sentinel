# Native pending-request lifecycle handoff — issue8

Stacked on PR20 raw-byte validation. Internal Rust API in sentinel_proto::native_pending. This does not register a host, authenticate browser/agent callers, perform a URL assessment, expand methods/permissions, stop workers or prove desktop connectivity. GLM/coordinator must review before wiring.

## Host sequence and signatures

1. Authenticate the browser origin and independently authorize agent IPC. Create one PendingRequests::new(Instant::now()) -> Result<PendingRequests,PendingError> per actual port. The process-local non-wrapping atomic session reference is correlation, not identity. Do not expose it on the wire.
2. read_chrome_request remains the bounded raw-byte ingress. Close transport/schema failure as documented; do not reconstruct requests through serde Value. Only validated NativeRequest::Capabilities or ::Url can reach admit(&NativeRequest,Instant) -> Result<PendingTicket,PendingError>. Time is the trusted host monotonic clock, never a request argument. Retained data is the bounded ID only; URLs/subjects are not copied into this registry. Caller still owns reviewed subject/tab/navigation binding and narrow assessment dispatch.
3. Before submitting an actual response, call complete(PendingTicket,Instant) -> Result<String,PendingError>. Only Ok(id) authorizes the reply within this session's lifetime/deadline. Ticket fields are private, Debug redacts IDs, and cloned tickets cannot complete twice. Complete before writing under the port owner's serialization; disconnect must not interleave an authorized response into a different port. This helper supplies no write timeout or transport atomicity.
4. Trusted timer calls expire(Instant) -> Result<Vec<String>,PendingError>, at most32 sorted correlations, removing expired entries exactly once. Emit fixed timeout/unavailable responses in the same still-authenticated port and separately request cancellation/reap of work. Timeout is not proof of worker termination. Missed timer calls do not allow late success: complete checks the deadline independently. Expired entries occupy admission until complete/expire; no implicit hidden queue.
5. disconnect() irreversibly closes and empties this instance; pending_count() -> usize is redacted diagnostic only. Cancel/reap owned work separately. Reconnect needs a newly authenticated instance; old tickets cannot authorize it. No disconnect/timeout response restores availability.

Examples: new host session at t0 -> admit validated capabilities IDcap1 -> ticket -> complete before t0+5s yields cap1 once. URL IDurl1 reaching t0+5s expires; later callback yields Unknown (or Expired when complete performs expiry first) and must not update UI/history. A new session holding its own IDcap1 rejects the old session's ticket as Foreign without removing its new pending entry.

## Bounds and states

At most32 pending; Busy adds no work/history. Fixed5000ms deadline aligns with draft v1. IDs1–128 ASCII alphanumeric/_/-; InvalidId rejects manually constructed invalid enums as defense in depth. Every admitted ID is sealed for the session, including success/timeout; Replay never requeues it. Unlike an unbounded replay set, at most256 IDs may be admitted over a session lifetime. SessionBudget means drain/cancel and close this port, then explicitly reconnect/authenticate with fresh nonce/IDs. Do not reset the registry in-place or silently discard replay history. This conservative bounded host lifetime is a proposed operational limit for peer review; the extension's monotonic-counter-plus-port-nonce ID generator remains unimplemented.

Closed rejects admission/completion/expiry permanently. Unknown covers already consumed/expired/unsolicited ticket IDs; Foreign covers another process-session instance, without releasing a valid pending entry. ClockRollback leaves maps unchanged and requires correction of trusted local timer calls. Atomic-session exhaustion or Instant overflow yields Unavailable, never wrapping references. None is a malicious/clean website verdict. No browser wire DTO/binding is added: this is native private state; all UI error/capability mappings and live journeys remain pending.

## Trusted explicit cancellation - 5 October 2026

`PendingRequests::cancel(&mut self, ticket: PendingTicket, now: Instant) -> Result<(), PendingError>` consumes one current session ticket through the same validation/deadline path as completion. Use it when a trusted subject/tab/navigation changes or a warning is dismissed. It is not a new browser method, content-script endpoint, user identity, or authorization to stop an unrelated operation.

Before invalidating the visible subject, the serialized host owner should cancel its retained ticket, invalidate the corresponding view, and separately cancel/reap the owned work. On-time cancellation returns `Ok(())`, releases its pending slot and suppresses all later completions of cloned tickets (`Unknown`). The ID remains sealed in replay history and counts toward the existing 256-admission lifetime budget. An invalidated subject must not display or log success from a later callback, even if work itself completed. Do not re-admit the same ID or treat dismissal as a safe URL assessment.

Foreign tickets return `Foreign` without consuming the current session's request. `Closed` remains terminal. `ClockRollback` leaves the pending entry unchanged: correct the host-owned clock call or disconnect the session conservatively; never allow a stale view to remain actionable. Cancellation at or after the 5-second deadline removes the pending entry and returns `Expired`; a later callback becomes `Unknown`. Already completed/cancelled/timer-expired tickets return `Unknown`. No cancellation success implies worker termination or a delivered wire response. Cancellation sends no response and exposes no correlation result by itself; the authenticated port adapter still owns any fixed lifecycle notification, subject binding and actual transport deadlines.

Reproducible native sequence: admit validated ID `url1`, retain a clone for the async callback, then cancel the owner ticket before expiry. Cancellation returns `Ok(())`; callback `complete(clone, now)` returns `Unknown`; re-admission of `url1` returns `Replay`; an unrelated admitted request can still complete. No URL, secret or page body is retained or emitted by this helper. No browser DTO changes are needed for this private native operation; UI must consume the eventual reviewed adapter's subject invalidation/unavailable state.
