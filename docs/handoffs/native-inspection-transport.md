# Real scan process transport — tomorrow demo

Entry point: `cargo build -p sentinel-av --bin sentinel-inspect`; native parent launches the trusted executable with `--file <selected-path>` or `--folder <selected-path>`, without a shell. Native picker supplies the selected path; never accept a browser-provided filesystem path. Stdin receives a bounded cancellation command (`cancel` plus newline); malformed nonempty commands also request cancellation. An open stdin keeps cancellation available; the parent must terminate/reap on shutdown. Process separation is not restricted-token, memory-limited or network-denied isolation.

Stdout is NDJSON of authoritative `ScanJobSnapshot` DTOs, only when real progress/state changes. Reports are path-free canonical `FileInspectionSnapshot`s. Worker finished means acquisition ended, not complete coverage/safety. Fixed error output carries no source path or raw content. The child retains selected subject/ancestry throughout the actual worker lifetime and applies existing limits. It does not load an external hash database, unpack archives, perform remediation or retain a quarantine session after exit.

`apps/demo-runtime/native-inspection.mjs` exports `inspectNative({executable,path,kind,onSnapshot,cancelled,timeoutMs})`. Defaults: 35 seconds parent deadline, 50 ms cancellation poll, one second grace before owned child kill, 2 MiB total stdout/stderr and 64 KiB report-line bound. Shell disabled and window hidden. It consumes closed/redacted canonical output, refuses changed correlation and snapshots after terminal output, requires successful exit plus terminal snapshot, and waits for close after cancellation/timeout. Return `{status,snapshot}` distinguishes unavailable, failed, cancelled, timed_out, finished. None means unavailable evidence, never clean. This module is not wired into server.mjs or the UI yet.

Actual evidence: two Rust process tests read unchanged harmless25-byte file, validate path-free SHA/report and refuse E: before access. Five Node adapter tests use the actual Rust executable: missing executable, unchanged real25-byte acquisition plus forged output validation cases, harmless64MiB zero-filled file (8MiB acquired, partial/null SHA, padding clue), harmless128-byte disguised PE header cancellation before launch, actual running-child cancellation and parent timeout with unchanged source size. Test-only `SENTINEL_TEST_INSPECT` locates the actual build; production has no client-supplied executable configuration.

Reproduce on Windows: set the configured Rust toolchain/MinGW PATH; run `cargo test -p sentinel-av --test inspect_process`; set `SENTINEL_TEST_INSPECT` to the built `target/debug/sentinel-inspect.exe`; run `node --test apps/demo-runtime/native-inspection.test.mjs`. All samples are owned harmless temporary files. No E: access, malware execution, Defender change or valuable-file quarantine.

## Desktop runtime connection

Stage the locally built executable with tools/stage-inspection-engine.ps1 -EnginePath <owned build output>; optional StripToolPath strips debug symbols only from the copy. This writes inspection-engine.json with source and staged digests. tools/package-demo.ps1 now refuses a missing or digest-mismatched engine before creating its output directory, and includes the receipt. The receipt proves byte identity only; rerun native tests against the staged executable before publishing a candidate.

Local staged-copy evidence: ten native runtime/parent/DFI tests passed against apps/desktop/console-build/sentinel-inspect.exe, including missing configured engine with no synthetic fallback, actual scan/quarantine/restore and deadlines. Staged SHA256 f7b8f9b4c8fa0c9cb2e32aed5baaa93c4599efa044c0b07094b60bd9a3e55435, 133676274 bytes. This remains an unpinned local candidate, not full portable packaging or visible/offline rehearsal acceptance.

The command-line demo runtime selects the trusted packaged engine at apps/desktop/console-build/sentinel-inspect.exe. It does not accept an executable from requests or fall back automatically when that engine is missing. Packaging must still install this binary. startRuntime accepts nativeExecutable only as native bootstrap configuration; omitted configuration retains the older synthetic test harness for existing tests.

The authenticated desktop /scan invokes the Rust scanner with native-selected path and inferred file/folder kind. /cancel and shutdown reach its cancellation lifecycle. POST /inspection with empty body returns {snapshot: ScanJobSnapshot|null}; browser callers are forbidden. The legacy /state shape remains compatible: completed full-digest reports are projected there, while canonical partial-byte evidence remains at /inspection until the accepted shared UI contract is integrated. Scan coverage remains partial even when individual files are completed. Missing/failed engine is failed, never a clean result. native-runtime.test.mjs verifies actual HTTP-to-Rust byte digest/count, source preservation, redacted evidence and browser refusal. No installed desktop UI or browser download acceptance is established by this test.
