## Source correlation resolved

The partial-query cause was reproduced: this host successfully returns a zeroed35-byte connection-information record, including index0/status0, for empty ports. The parser now accepts only successful, adequately bounded status0 responses whose entire returned metadata is zero and whose index is0 or the requested port. Connected responses still require an exact index and driver-key match; failed queries remain unresolved. A review-found trailing-data gap has a failing-then-passing regression. The repeated live parent query returns one `internal_port_candidate`, complete enumeration, no exemption. See [port evidence](evidence/usb-internal-keyboard-port-2026-10-14.json).

The sandbox could receive Raw Input while native hub access was unavailable, so the guided instrument was launched outside sandbox device-access restrictions, with its launcher waiting for exit. Owner-guided native-access observations correlate three Ctrl presses to the internal-port candidate. This is source/port evidence, not a policy-enrollment operation.

`GetPointerDevices` returned zero devices on this host. The instrument therefore registers the precision-touchpad HID usage directly: page0x0D/usage5. It checks type2 report sizes/counts against the received buffer, maps the exact source handle privately, and requires full ACPI/I2C/touchpad-usage metadata before counting it. Report contents and pointer coordinates are never parsed or logged. The owner-completed check captured three keyboard events with internal-port evidence and521 touchpad Raw Input packets with platform ancestry;492 additional device-zero movement events remain unattributed. [Captured evidence](evidence/usb-internal-source-proof-2026-10-14.json) has `policyChanged=false` and `internalExemptionVerified=false` because no installed exemption/enrollment was applied.

The source-mapping prerequisite is now observed on this laptop. Other laptops must rerun discovery/proof; names and this laptop's IDs are not portable exemptions. Remaining activation prerequisites include a tested recovery/fallback path, authenticated privileged authority, installed watchdog and actual first-input blocking trials. The owner deferred recovery verification and requested code tests; no blocking trial was run.
