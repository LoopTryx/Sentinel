CyberShield — Product Requirements Document (v1.0)

Audience: an autonomous AI coding agent + the human owner (Loop). How to use this doc: read §0–§6 fully, then execute Phase 1 milestone by milestone (§9), then Phase 2 (§10). Never start Phase 2 before the Phase 1 gate passes. Date: 29 Sep 2026 · Primary platform: Windows 10/11 (x64) · Type: defensive security software only.

0. TL;DR
CyberShield = antivirus-grade protection + a teach-as-you-protect awareness layer + built-in password manager, delivered as a desktop app + Windows service + browser extension that talk to each other.
Hero differentiators (build these best):
Shield Dock — BadUSB / rogue-USB quarantine. New USB devices are held, analysed, and only "mounted" after they pass.
Wi-Fi Guard — rogue router / evil-twin / DNS-hijack / traffic-tamper detection with a plain-language Trust Score.
Awareness Engine — 25+ interactive "teachable moment" cards (e.g. Password Autopsy).
Also: file inspection, real-time AV, ransomware guard, Web Shield, Mail Guard (Gmail/Outlook web), Chat Guard (WhatsApp Web), password vault, system hygiene audit.
Two master phases: Phase 1 = everything works (headless-first, plain UI) → Phase 2 = everything is beautiful (glass UI, motion, a11y, i18n).
1. Vision & positioning
One-liner: "The antivirus that explains itself — and defends the places other antiviruses ignore (USB ports and Wi-Fi)."
Why now: most AVs are file-scanners. Attacks now arrive via USB keystroke injection, evil-twin Wi-Fi, phishing mail, and WhatsApp scams. Users don't know why something is dangerous, so they click through warnings.
Positioning: a layered second-opinion suite that runs alongside Microsoft Defender (see §5-R1), not a Defender replacement.
Design goal: looks like a premium privacy product (calm, glassy, purple/cyan gradients, one big status hero — Proton VPN–style clarity), with accessibility built-in.
2. Principles (non-negotiable)
Privacy-first / local-first. File contents, emails, chats, and passwords never leave the device. Network lookups use hash prefixes (k-anonymity) or public feed downloads.
Defensive only. No deauth, packet injection, credential brute-forcing, keylogging of users, or exploit code — ever. Test payloads are benign (see §11).
Honest failure. If a check cannot run (no admin rights, no network, unsupported edition), the UI/log says so explicitly. No silent fallbacks and no fake "All clear".
Explain every verdict. Every block/warn carries reasons[] in plain language + evidence.
Fail-safe. A protective feature must never lock the user out of their own machine (especially USB policy — see F3).
Headless-first. All logic reachable via a typed API/CLI so Phase 2 is a pure re-skin.
Ship small, verify each step. Every milestone has acceptance tests and a demo script.
3. Personas
P1 — Everyday user (student/family): wants "am I safe?" in one glance; needs plain language.
P2 — Curious/tech user: wants details (hashes, descriptors, BSSIDs, YARA hits).
P3 — Parent/teacher (later): wants a hygiene score + lessons.
4. Scope

In scope (v1): Windows desktop app, Windows service, Chrome/Edge/Brave extension (MV3), Firefox extension (Phase 1 stretch), all features in §8. Out of scope (v1): macOS/Linux/Android/iOS clients, kernel minifilter driver (backlog B1), cloud backend/sync (backlog B3), parental controls, VPN.

5. Reality checks the agent MUST design around
#	Constraint	Design consequence
R1	Only Microsoft-vetted partners register as the primary AV in Windows Security Center.	CyberShield runs beside Defender. Don't disable/tamper with Defender. Read its state via WMI root\SecurityCenter2.
R2	True pre-execution blocking of every file open needs a signed kernel minifilter (needs EV/attestation signing).	v1 = user-mode real-time (FS change notifications + USN journal + ETW process events). Document the gap; minifilter = backlog B1.
R3	A "sandbox simulation" cannot execute-test a USB's firmware; a BadUSB acts as a keyboard within milliseconds of enumeration.	Primary defence = block-before-install via Windows device-installation policy (F3), then analyse descriptors, then scan storage, then release. Runtime keystroke-timing monitor is a second layer.
R4	Windows Sandbox / Hyper-V exist only on Pro/Enterprise/Education, not Home.	F3 has Tier A (all editions: isolated user-mode parser) and Tier B (Pro+: Windows Sandbox detonation). UI must show which tier is active.
R5	Windows can't put a normal Wi-Fi NIC in monitor mode → can't see raw deauth/beacon frames.	Wi-Fi Guard uses WLAN API scan data + gateway/DNS/TLS/HTTP behavioural tests. Say "cannot detect deauth floods on this adapter" honestly.
R6	Npcap redistribution has licensing limits.	v1 avoids raw packet capture; use OS APIs (GetIpNetTable2, WLAN API). Npcap-based features = optional/backlog.
R7	WhatsApp mobile/desktop app content is not accessible.	Chat Guard works on WhatsApp Web via content script only. Selectors live in one config file (WhatsApp changes DOM often).
R8	Manifest V3 limits blocking webRequest.	Use declarativeNetRequest (static + dynamic rules) and a service-worker–friendly design (no persistent background page).
R9	Free intel APIs have terms/limits: Google Safe Browsing = non-commercial use; VirusTotal free ≈ 4 req/min & 500/day; HIBP email search needs a paid key, Pwned Passwords range API is free.	Cache aggressively, prefer local feeds, make every online source optional & pluggable; decide commercial status (see §14).
R10	Reading browsers' saved-password DBs is infostealer behaviour and blocked by OS-bound encryption.	Import passwords only via the user's CSV export or extension-captured form submits (explicit consent).
R11	Crack-time numbers are estimates.	Always label "estimated", show the attacker model used.

7. Cross-cutting requirements
Verdict model (shared by all modules): Verdict { level: Safe|Info|Suspicious|Dangerous|Unknown, score: 0-100, reasons: Reason[], evidence: Evidence[], actions: Action[], teach?: AwarenessCardId }
Event bus: every module emits AwarenessEvent { id, type, severity, subject, evidence, teach_id, ts }. The awareness engine decides whether/when to teach (rate-limited, dismissible, never nagging).
Logging: structured tracing → rotating local log; in-app Activity Log; export button. No PII in logs (hash/redact paths' user segment).
Config: TOML + UI; every feature has an on/off switch and a "learn more".
Update system: signature/feed updater (scheduled, resumable, integrity-checked with hashes/signatures) separate from app updater.
Performance budgets: idle RAM: UI ≤ 150 MB, svc ≤ 80 MB; idle CPU < 1%; quick scan on 100k files < 60 s on SSD; cold start UI < 2 s; extension bundle < 1 MB (excl. ONNX model).
Self-protection: service ACLs, signed updates, tamper-check of own binaries/rules, anti-injection for the pipe, no secrets in logs.
i18n-ready from day 1: all strings via keys (i18next), logical CSS properties (RTL-safe). Languages targeted: English (v1), Arabic + Hindi + Malayalam (Phase 2).
8. Feature specifications
F1 — Core Antivirus Engine
On-demand scans: Quick (user dirs, startup, temp, downloads), Full, Custom folder, Removable drive, "Scan this file" (shell context menu).
Detection stack (in order): allowlist/known-good (Authenticode + Tranco-like trust for publishers) → hash reputation (local MalwareBazaar cache, optional VT hash) → ClamAV signatures → YARA-X rules → heuristics (PE anomalies, high entropy sections, suspicious imports, packers, script obfuscation, Office macros, PDF JS, LNK abuse, double extensions).
Real-time (user-mode): file create/modify watcher (ReadDirectoryChangesW + USN journal), process-start events via ETW (Microsoft-Windows-Kernel-Process), new-download hook via the extension. Scan-on-write for Downloads/Desktop/Temp/USB; debounce + size limits.
Ransomware Guard: canary files in user folders; alert + suspend suspect process on mass-rename/mass-encrypt patterns (entropy jump + extension churn); protected-folder list.
Quarantine: encrypted, ACL'd vault (AES-GCM per item, metadata DB); restore/delete/submit-hash; never executes quarantined content.
Persistence audit: Run/RunOnce keys, scheduled tasks, services, startup folder, WMI subscriptions, browser extensions list, hosts-file tamper → flagged with explanations.
Network connection monitor: list live connections per process, flag IPs/domains on threat feeds (read-only, no blocking in v1).
Acceptance: EICAR detected in files/zip/nested zip; YARA test rule hits; quarantine round-trip works; ransomware-canary simulation (benign script that renames files) is flagged in < 5 s; zero crashes on a corpus of 10k mixed clean files.
F2 — File Inspector (deep, single-file report)
Drag-and-drop or right-click → report: hashes (MD5/SHA-1/SHA-256/ssdeep-style fuzzy), true type vs extension, size, entropy, signer/cert chain, PE sections/imports/resources, embedded URLs/IPs, strings of interest, macro/JS/script extraction (view-only), archive tree (safe, bomb-limited), timestamp anomalies, reputation lookups, YARA/AV hits.
Verdict + "Why?" panel (plain-language reasons) + Teach card ("Why a .pdf.exe is a trap").
Never executes the file. Parsing runs in a restricted child process (job object, low integrity, no network, memory/time caps).
Acceptance: 20 sample types produce correct type/verdict; malformed/fuzzed inputs never crash the host (fuzz with cargo-fuzz 30 min per parser in CI nightly).
F3 — Shield Dock (USB Protection) ⭐ hero feature

Goal: no unknown USB device gets to type, mount, or install a driver until CyberShield has inspected it and the user approves.

Pipeline

Baseline (first run): snapshot currently attached keyboards/mice/hubs/storage → auto-allow-list them (by hardware ID + instance/serial). Also allow built-in/PS/2/Bluetooth/internal HID classes so the machine is never locked out.
Block-before-install: enable Windows Device Installation Restrictions (HKLM\SOFTWARE\Policies\Microsoft\Windows\DeviceInstall\Restrictions — deny-unspecified + allow-list of trusted IDs/classes) managed by shield-svc. New devices enumerate but no driver binds → no keystrokes, no drive letter.
Quarantine state: device shown as "Held — inspecting". Read PnP properties without binding drivers (Hardware IDs, Compatible IDs, Class GUIDs, container ID, child interface nodes MI_xx, serial, manufacturer strings, bus-reported speed/power).
Descriptor risk analysis (rules, weighted):
Storage device that also exposes an HID/keyboard interface (composite) → Dangerous.
Claims keyboard/HID but no serial, generic/DIY-board VID/PID (dev boards, known keystroke-injector families), or VID/PID that mismatches its claimed vendor string → Suspicious+.
Advertises network adapter (CDC-ECM/RNDIS) unexpectedly (can hijack traffic/DNS) → Dangerous.
Unknown class combos, excessive interface count, fake "charge-only" that exposes data lines → flag.
Maintain data/rules/usb_vidpid.json (community-updatable, signed).
Storage inspection (Tier A — all editions): allow storage class only for this device, but keep it offline / no drive letter / read-only (disable automount for it, set disk read-only/offline via IOCTL/Storage APIs). Acquire a raw read-only image or stream sectors, parse FAT/exFAT/NTFS in an isolated user-mode parser process (not the kernel filesystem driver), then run F1/F2 pipeline on every file. Extra USB-specific checks: autorun.inf, hidden/system-attribute folders + .lnk "shortcut virus" pattern, executables masquerading as folders, oversized .lnk args, suspicious scripts in root.
Detonation Chamber (Tier B — Pro+/Windows Sandbox available): copy extracted files into a networkless Windows Sandbox session (generated .wsb, read-only mapped input, no clipboard/audio/GPU), execute only user-approved executables with a lightweight behaviour monitor (process/file/registry/network attempts via ETW inside sandbox), return a behaviour report. If unavailable → UI says "Tier A only (Windows Sandbox not available on this edition)".
Verdict & release: Clean → prompt: Allow (read-only) / Allow (read-write) / Keep blocked / Eject. Keyboard-class devices are never auto-released; user confirms via on-screen approval requiring a mouse/touch/or trusted keyboard (never approvable by the new device itself).
Runtime keystroke guard (second layer, for approved & baseline HID): Raw Input API per-device timing → flag sustained inhuman typing (default > 15 chars/s for > 1 s, or near-zero variance between keys), or Win+R / PowerShell / cmd launched within 5 s of a new HID appearing → freeze the new device (disable via PnP), kill spawned process tree, show "USB Autopsy" (replay of what it tried to type, in a safe view). Thresholds configurable; tune against real typists to keep false positives low.
Safety nets (mandatory): never allow-list-lock out all keyboards; timed auto-revert of policy if the UI can't be reached within N seconds ("recovery countdown"); "Emergency: allow all devices" reachable from tray + a documented Safe-Mode/registry recovery step; Bluetooth & internal devices exempt by default.
Modes: Strict (deny all new), Balanced (default: deny new HID/network/composite; auto-scan storage), Learn (log-only for 24 h after install).

Acceptance (use only your own lab devices): benign HID test device (e.g. Raspberry Pi Pico typing "hello" instantly) is held and never types before approval; storage stick with EICAR is detected before a drive letter appears; composite storage+HID is flagged Dangerous; existing keyboard/mouse keep working through install, reboot, and policy toggling; recovery path verified.

F4 — Wi-Fi Guard ⭐ hero feature

Inputs (no monitor mode required): WLAN API (WlanScan, WlanGetNetworkBssList, connection attributes), GetIpNetTable2/adapter info, DHCP lease info, DoH resolvers for cross-check, direct HTTPS/HTTP probes.

Checks → Trust Score (0–100) with reasons

Encryption posture: Open / WEP / WPA-TKIP / WPA2-PSK / WPA2-Enterprise / WPA3 / mixed transition mode → score + explanation.
Evil-twin / clone signals: same SSID with multiple BSSIDs having different security, vendor OUI, channel plan, or suspiciously strong RSSI; TOFU baseline for "home/school" networks (store known-good BSSID/OUI/security; alert on change); hidden-SSID mismatches.
Gateway integrity: gateway MAC vs baseline; duplicate MAC in ARP table / gateway MAC flips (ARP-spoof indicator); unexpected extra first hop; abnormal RTT/TTL to gateway.
DNS integrity: resolve canary domains via system resolver and via DoH (Cloudflare/Google/Quad9); mismatches, NXDOMAIN hijacking, private-IP answers for public domains, captive redirection → flag.
TLS / MITM check: fetch a few known HTTPS endpoints; verify chain validity and compare SPKI pin/fingerprint sets (pin list updated via signed feed); unexpected issuer = Dangerous.
HTTP tamper check: fetch small static HTTP resources with known hashes; injected content/ads/scripts → flag.
Captive portal analysis: detect via Microsoft NCSI / generate_204 style probes; portals that ask for passwords/cards/OTP → warn.
Router health (non-intrusive): vendor from OUI; gateway admin ports/services reachable from LAN (Telnet, UPnP exposed, HTTP admin without TLS) → advisory; "default credentials not changed?" is an advice card only — never attempt logins.
Rogue DHCP (stretch): detect more than one DHCP server responding (only if implementable without Npcap; else backlog).
Hotspot-look-alike heuristics: SSID similar to a known network but not identical (e.g., Free_Airport_WiFi vs Free-Airport-WiFi), phone-hotspot patterns in public places, SSIDs with homoglyphs.

Actions: Disconnect & forget, Force DoH, Suggest VPN, Block sensitive sites (banking/vault autofill) on low-trust nets (via extension), Public-Wi-Fi Mode (disables file-sharing/discovery, warns before logins). Modes: auto-check on connect, manual "Test this network", background re-check every N minutes. Acceptance: lab test with your own second router cloning your SSID with different security/OUI triggers Evil-Twin flag; DNS-tamper simulated via a local test resolver triggers flag; captive-portal network detected; results always list which checks could not run and why.

F5 — Vault (Password Manager)
Crypto: master password → Argon2id (tunable, benchmarked on device) → key-encryption; per-item XChaCha20-Poly1305; encrypted SQLite; recovery key/Emergency Kit (PDF/printable); auto-lock timer; lock on sleep/RDP; clipboard auto-clear (20 s) and clipboard-history exclusion flag; Windows Hello unlock (optional, WebAuthn/DPAPI-NG).
Items: logins, secure notes, cards (masked), identities, TOTP (RFC 6238), attachments (small).
Generator: length/charset/passphrase (EFF wordlist), pronounceable, live crack-time meter.
Import/Export: CSV from Chrome/Edge/Firefox/Bitwarden/1Password/LastPass; encrypted export; no direct browser-DB reading (R10).
Security Audit (feeds Awareness): weak (zxcvbn score ≤ 2), breached (HIBP range check), reused, old, missing 2FA (known-2FA-sites list), HTTP-only sites, similar-passwords (edit distance).
Password Autopsy data model (for the popup): { item, score, crack_times{online_throttled, online_unthrottled, offline_slow, offline_fast}, patterns[{type, span}], breach_count, keys_used[], suggestions[], fixed_candidate }
Acceptance: vault round-trips 10k items; wrong-password attempts rate-limited; memory zeroized on lock (verify in tests); HIBP check sends only 5-char prefix (assert in test via mock server); crack-time output matches zxcvbn reference on fixtures.
F6 — Web Shield (Extension core)
URL verdict pipeline: allow/deny lists → local Safe Browsing hash prefixes → URLhaus/OpenPhish/PhishTank cache → heuristics (punycode/homoglyph, typosquat distance vs Tranco top-N, suspicious TLDs, very young domain via RDAP, URL entropy, IP-literal hosts, deceptive subdomains, brand-in-path) → verdict.
Interstitial block page (bundled, works offline) with "Why blocked", "Go back", "Proceed anyway (logged)".
Download guard: on downloads.onCreated/Changed → hash + type check → hand to service for scan; warn on double extensions/.exe from unusual origins.
Login-page protection: password field on non-matching origin for a saved login → Phishing Alert; block autofill on lookalikes.
Tracker/ad blocking: declarativeNetRequest static rulesets (EasyList/EasyPrivacy-derived, license-checked) + dynamic rules; per-site toggle; counters.
Extension permission risk audit (awareness) and HTTPS-only upgrade.
Acceptance: known-bad test URLs (URLhaus test entries, Google Safe Browsing test pages) blocked; typosquat paypa1.com-style test domains flagged; block page shows reasons; MV3 service worker survives suspend/resume without losing state.
F7 — Mail Guard (Gmail / Outlook Web)
How: content scripts on mail.google.com, outlook.live.com, outlook.office.com read the open message DOM (read-only). All analysis local.
Signals: display-name vs address mismatch, look-alike sender domain, Reply-To mismatch, link text ≠ href, shorteners/punycode, dangerous attachment types/double ext, urgency/payment/gift-card/OTP/invoice language, QR-code images (quishing), mismatched brand vs domain, first-time sender + link, "[EXTERNAL]" spoof, header auth results where the UI exposes them (SPF/DKIM/DMARC).
Scoring: rules + tiny ONNX classifier (trained offline on public corpora like SpamAssassin/Enron-spam/phishing corpora — record dataset licences in DECISIONS.md).
UI hook: unobtrusive banner inside the email (Shadow DOM) with score, reasons, "Teach me" → awareness card ("Anatomy of a phish").
Acceptance: ≥ 90% detection / ≤ 3% false positives on the held-out test set; no network calls containing email text (assert in tests).
F8 — Chat Guard (WhatsApp Web)
How: content script on web.whatsapp.com; MutationObserver on the active chat; read-only (never sends/automates messages).
Signals: unknown-number first contact; country-code anomaly vs user's home region (configurable, default from OS locale); links (→ Web Shield engine); scam pattern packs (task/"like-and-earn" jobs, crypto/investment, fake delivery/customs, "send the 6-digit code", loan/KYC, romance/emergency, prize/lottery, impersonating a contact with a new number); rapid-fire group-invite spam; media with QR.
Number reputation: local blocklist (user reports + shipped list) → "Report as scam" (local first; community sync = backlog B3). Do not scrape third-party caller-ID services.
UI hook: small shield chip on the chat header + collapsible warning banner; one-tap "Block & report in WhatsApp" instructions (no automation).
Resilience: all DOM selectors in selectors.json; smoke test in CI against a recorded fixture; graceful "Chat Guard paused — WhatsApp layout changed" state.
Acceptance: fixture chats with each scam pattern flagged; benign chats not flagged; guard degrades gracefully when selectors fail.
F9 — Awareness Engine ⭐ hero feature

Concept: every detection is a teachable moment. Engine = triggers → card → micro-interaction → score.

Card tiers: (1) inline chip/banner, (2) modal/popover interactive card, (3) full lesson (2–4 min, gamified). Rate-limited (max N/day, snooze, "don't show again", per-topic mastery reduces repeats).
Cyber Hygiene Score (0–1000) + streaks + weekly report; explains how to gain points; never shames.
Data-driven: lessons live in data/awareness/*.json (steps, media refs, quiz items, i18n keys) so content can grow without code changes.

F10 — System Hygiene Audit

Defender/firewall/SmartScreen/BitLocker state (via WMI/registry, read-only), Windows Update status, risky settings (SMBv1, RDP exposed, AutoRun, UAC level), open listening ports, outdated apps (winget list vs KEV/OSV where matchable), browser hardening checklist. Output = score + fix-it guidance. No auto-changing of OS settings without explicit click.

F11 — Threat Intel Layer (shield-intel)
Scheduled feed sync with ETag/If-Modified-Since, integrity hashes, size caps, backoff; local SQLite/bloom filters for fast lookups.
Sources: Safe Browsing (hash prefixes), URLhaus, OpenPhish/PhishTank, MalwareBazaar, ThreatFox (IOC), Tranco, CISA KEV, OSV; optional VT/HIBP-email with user-supplied keys.
Each source has: licence note, refresh cadence, on/off, last-sync status shown in UI. Offline mode works from cache and says so.
F12 — Settings, Privacy, Updates

Per-feature toggles, protection profiles (Balanced/Strict/Learn), exclusions, telemetry off by default (opt-in, anonymous counters only), data export/delete, app + rule auto-update with signature verification, diagnostic bundle export (redacted).

10.1 Design language: "Aurora Glass"
Feel: calm, trustworthy, premium — status-first like Proton VPN's clarity (one big protection hero, minimal chrome, left sidebar, friendly explanations), but with CyberShield's own identity (shield ring, aurora gradient).
Dark-first with a full light theme and high-contrast theme.
Glass rule (critical): glass is for chrome and containers (sidebar, cards, popovers, nav). Body text and dense data sit on a more-opaque inner layer that guarantees WCAG 4.5:1 against the worst-case backdrop. No text directly on raw blur.
Backdrop: slow-moving aurora gradient blobs (paused when window unfocused / reduced-motion), plus a subtle noise overlay for depth.
Real OS materials: use window-vibrancy for Mica/Acrylic on Windows 11 (Acrylic on Win10 has drag-lag — provide setting to disable); CSS backdrop-filter inside the WebView.

11. Testing & QA (safe by design)
AV: EICAR + zipped/nested EICAR; benign "suspicious-looking" fixtures for heuristics; YARA unit rules; large clean corpus for false-positive checks.
USB (own hardware only): a benign HID test device (e.g., dev board that types a harmless string at inhuman speed); storage stick containing EICAR + a decoy autorun.inf + shortcut-pattern fixtures; composite-device fixture. Never use real malicious payloads.
Wi-Fi (own network only): second router/hotspot you own configured to mimic your SSID with different security/OUI; local test DNS resolver returning wrong answers; local HTTP server that injects a harmless marker.
Extension: Playwright with real Chromium + extension; Gmail/Outlook/WhatsApp recorded DOM fixtures (no real accounts in CI).
Vault: property tests (encrypt/decrypt), KDF benchmarks, zeroize checks, tamper tests.
Fuzzing: cargo-fuzz on PE/OLE/PDF/archive/FS parsers (nightly).
VM matrix: Win10 22H2 + Win11, Home + Pro, with/without admin, with Defender on.
Security review: threat model for the pipe, native host (validate extension IDs allow-list), extension messaging, update channel.
12. Security of CyberShield itself (threat model summary)
Named pipe: ACL to the interactive user + SYSTEM only; per-session token; strict message schema; size/rate limits.
Native messaging host manifest allow-lists exact extension IDs; never accept arbitrary origins.
Extension: minimal permissions (justify each in DECISIONS.md), CSP strict, no eval, content scripts talk only via runtime.sendMessage; page scripts can never read vault data.
Updates: signed manifests, pinned public key, rollback protection.
Vault: keys in user process memory only, zeroize on lock, no plaintext on disk/logs, secure clipboard handling.
Supply chain: cargo-deny, cargo-audit, npm audit, lockfiles, SBOM at release.
13. Agent operating rules (copy into AGENTS.md)
Read the milestone spec, then plan in ≤ 10 lines, then implement. Ask the owner only when blocked on an item in §14.
Output complete files (no "…rest unchanged" snippets). Keep commits small and buildable.
Test-first for logic; every milestone ends with: tests green, demo script (docs/demos/Mx.y.md), STATUS.md updated.
Honest failure reporting: never swallow errors or fake success; surface "cannot run because…" in UI + logs.
No offensive capability. If a task seems to need deauth/injection/bruteforce/keylogging-of-user, stop and log it — find a defensive alternative.
Don't over-engineer: prefer the simplest approach that meets acceptance criteria; log alternatives in DECISIONS.md (ADR: context, options, decision, consequences).
Lockout safety: before touching device-install policy, implement + test the revert path first.
Privacy checks in tests: assert that no network request contains file contents, email/chat text, or full password hashes.
Design references: use the links in §15 as human-curated inspiration. Do not scrape sites that forbid crawling; the owner will drop screenshots into design/refs/. Build from tokens, not from copied assets.
Licensing hygiene: record licence for every dataset/rule pack/library in DECISIONS.md; no GPL contamination without an explicit decision (ClamAV is GPL — isolate as a separate process/dynamic boundary and document).
Definition of Done (per feature): code + tests + docs + telemetry-free + a11y hook (strings via i18n keys) + Awareness event emitted.
