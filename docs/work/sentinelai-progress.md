## Connected implementation

- `apps/desktop/SentinelNim.cs`: provider interface and real fixed-endpoint NVIDIA HTTP adapter. No redirects, cookies, proxy, tools, retries or automatic fallback. Bounded request, output, timeout and cancellation; structured interpretation with evidence-reference validation. HTTP error bodies are never exposed or logged.
- `SentinelAiNative.cs`: native masked key-entry/settings and exact-body consent dialogs. Windows Credential Manager generic credential `LoopTryx/Sentinel/NVIDIA-NIM/v1`; provider key never enters WebView, extension, localStorage or plaintext files. Model/timeout persist separately. Credential Manager isolates Windows users, **not malicious applications already running as the same user**. Removing the key invalidates in-flight results and cancels the current request; cancellation cannot undo transmission already completed.
- `GlassConsole.cs` / `build-console.ps1`: actual WebView method dispatcher calls the native provider. Authoritative findings are resolved through the existing authenticated runtime, not accepted from renderer descriptions. Native consent applies to the immutable exact HTTP body shown, including system instruction, model, question and attached evidence. New submissions require new consent.
- `apps/ui/src/views/SentinelAiView.tsx`: console navigation, local evidence, session conversation, provider settings/test/remove, composer, loading/cancel/error states. Conversation is bounded to forty displayed messages, held only in memory, and is never automatically attached to a request. Responses render as text, never executable HTML or action commands.
- `apps/demo-runtime/sentinel-ai.mjs`: local reassessment using the existing URL engine, not an additional detector. Random stable finding references, five-minute expiry, bounded queue/cache/nonces, replay rejection and one-time inbox consumption. Browser-reported blocked/scan/confidence fields are rejected. URL credentials, query and fragment are excluded from transferred findings; path may still contain personal information and is shown before transfer/cloud consent.
- Existing authenticated browser token, extension ID/origin checks and native pairing remain in force. Browser handoff can create local evidence, never upload to NVIDIA. Only desktop plus native-action token can publish an approved provider interpretation. It cannot change a URL verdict.
- `apps/extension/src/warning.js`, `navigation-policy.js`, `ai-handoff.js`: immediate offline explanation, original URL retained in the local redirect fragment for reassessment, local-transfer preview, explicit Ask SentinelAI, bounded five-minute session retry, desktop focus through a fixed native event, and return of a desktop-approved interpretation to the warning page. Existing dynamic rules need toggling off/on to adopt the new redirect format. Older warnings without an original URL remain useful but cannot fabricate a finding.
- `crates/sentinel-proto/src/sentinel_ai.rs`: authoritative output DTOs; TypeScript generated by ts-rs, consumed by the console.

## Contracts / entry points

WebView methods (exact console origin, visible foreground required for settings/send):

| Method | Input | Result / semantics |
|---|---|---|
| `ai.status` | `{}` | provider/model/configured/busy/timeoutSeconds/retention; never key |
| `ai.settings` | `{}` | native key/model/timeout dialog, then status |
| `ai.remove` | `{}` | cancel/invalidate current request, delete credential, return status |
| `ai.test` | `{}` | native preview of a fixed non-finding test question; real inference only after approval |
| `ai.send` | `{question, findingRef: string|null}` | resolve reference, native exact JSON preview/consent, bounded NVIDIA request, structured interpretation |
| `ai.cancel` | `{}` | cancel current native request; delivery to provider may already have occurred |
| `ai.inbox` | `{}` | consume next unexpired authenticated browser handoff once |

Authenticated runtime routes:

- Browser `POST /ai-handoff`: `{url, question, nonce}`. nonce is 32 lowercase hex characters; URL at most 2048 bytes, question at most 1000 characters, total request bounded to 4096 bytes. Response `{handoffId,finding,question,expiresAt}`. No implicit claim that a browser block occurred.
- Desktop `POST /ai-inbox {}` and `/ai-finding {ref}`: retrieve authoritative session evidence. Unknown/expired reference fails closed.
- Native-authorized desktop `POST /ai-answer {ref,result}`: validate references and store the interpretation separately from the finding.
- Browser `POST /ai-result {ref}`: return approved interpretation, or null while none exists. No inference is started by reading it.

Safe example: `https://example.test/winner-payment`, question `Why is this concerning?`. The local runtime reports reward/payment wording, not proof of malware. The provider receives only the displayed request body and authorization header, never the vault, files, previous conversations or browser history.
