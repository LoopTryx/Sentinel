# Password-field popup and autofill — extension 0.2.36

Owner requested a field icon, compact vault popup and automatic filling for saved logins; screenshot showed Chrome sidePanel.open losing its required transient user gesture.

Implemented a separate extension popup window, replacing the sidePanel.open call. It remains available across native Hello verification and uses no intermediary website. A 28 px shield control is visually placed inside supported HTTPS password inputs; mutation, scroll, resize and transition/animation events handle SPA fields and movement. Up to 64 fields are tracked. Controls are accessible in an open shadow root and reject untrusted scripted click events. A synthetic browser fixture confirmed the rendered field icon and a trusted click requesting its picker; no credentials used.

An explicit icon click creates a site/tab/document/field-bound request. The compact popup invokes the native autofill operation. Native broker validates exact HTTPS origin, verifies Windows Hello once and unlocks with the Windows-protected random key. One exact-origin account is filled into the bound field; multiple accounts return metadata for selection. Credentials go from native broker to extension worker to the bound document, never into the popup response or URL. Rechecking tab origin plus Chrome document ID prevents stale navigation fill. A unique per-field identifier prevents focus moving to another field during Hello from redirecting the fill; the review finding was fixed and the actual injection function regression confirms A fills, B remains empty, and replay after consuming the marker is rejected.

Registration/new-password fields open the generator, rather than automatically reusing existing credentials. Username selection prioritizes explicit username/email inputs and avoids filling an arbitrary search field. No automatic form submission or page-load autofill added. Save prompts remain explicit.

Website tools require owner-granted HTTPS host permission. Enable registers the script and attempts injection into the original tab immediately. Existing tabs should be refreshed after an extension reload; already-injected old scripts are not treated as upgraded merely because files changed.

Verification: 182 extension/runtime/vault checks passed, source/dist smoke passed, native connector and console compiled, independent read-only security review completed with previous field-binding issue resolved. Installed all six known extension copies as 0.2.36 and updated native broker with rollback backup. Installed native hash matches source; connected console startup confirms Dashboard. Live Chrome host permissions, real Windows Hello approval and real site sign-ins remain owner acceptance; no private credentials entered or captured by the agent.
