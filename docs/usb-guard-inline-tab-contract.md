# USB Guard inline-tab boundary

The USB Guard React tab renders only freshly classified external USB HID subjects. Built-in safety candidates remain exclusively native and cannot be selected by renderer requests. Block/Allow use broker-issued per-session opaque references and a topology token, never raw hardware IDs, commands, paths, or serialized owner proofs.

Native host methods: `usb.admission.snapshot {}` and `usb.admission.action {action:"block"|"allow", ref:<64 lower hex>, topology:<64 lower hex>}`. A fixed protected elevated operator owns the authenticated local pipe. Both peers verify the other's process PID/start/session; the host pins the installed executable/ACL before starting it. Pipe payloads have bounded framing and request nonce correlation. A pipe connection is transport authorization only. Fresh native classification and real Windows Hello remain necessary for every device policy change.

Snapshot: `{schemaVersion:1, topology:string|null, active:boolean, deadline:string|null, devices:[{ref,name,access:"allowed"|"restricted"|"off"|"unverified",canChange:boolean,canScan:false}], message:string}`. No Windows IDs or paths cross into the renderer. `canScan:false` means no verified volume-to-device scan authority exists; the UI must disable Scan rather than scan an unrelated folder or pretend to scan HID firmware. Device actions return a fresh snapshot. Native Hello may briefly show its owned confirmation/progress surface; management rows stay in the tab. Unknown, expired and failed readback never become “Blocked”. Existing five-minute recovery lease is unchanged; no silent renewal is authorized by this UI work.

Acceptance: pure framing/auth/refusal tests; UI action and internal-device omission tests; host/operator builds; independent boundary review; actual installed native pipe snapshot; then owner-operated Hello Block/Allow and physical keyboard/benign Ducky return tests. Fixtures do not prove input restoration. Pipe loss does not cancel an in-flight recovery transaction or its independent expiry task.

Update: normal tab browsing is now unprivileged and never starts the elevated operator. A snapshot may carry `verified:false`; all fallback access values are unverified, and active:false in that case does not establish policy absence. Host and privileged operator share the per-host session reference salt and pure native grouping code. Background refresh has no foreground gate. Actual actions remain explicitly confirmed, foreground-bound and Hello-authorized. Failed refresh keeps device names only, marks stale status and disables actions until refreshed.
