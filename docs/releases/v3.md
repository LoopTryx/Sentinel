# Sentinel v3 preview

This release combines Engineer B's v3 UI, Watchtower and quarantine work through commit 7967e35 with Engineer A's USB, SentinelAI, native connection and recovery progress. It is a Windows x64 preview, not a claim of completed general USB quarantine.

## Included

- Existing USB Guard device access controls and Windows Hello owner verification. Persistent saved decisions, named-device actions and truthful unverified/reconnect/restart states. Guard off by default.

- Supplied shield logo without the wordmark, used for console branding, app/taskbar/tray, installer/shortcut and Chrome icons.
- Compact hover-expanding navigation, centred icons/labels and F11 fullscreen. Native regression: 1080x740 -> fullscreen ->1080x740.

- Enter-to-send chat, Shift+Enter newline and IME-aware input.

- Encrypted local completed chat history and on-device Qwen2.5 1.5B Q4_K_M, NVIDIA optional.

- Opted-in supported WhatsApp/Gmail/Outlook message surfaces, bounded visible-message context, contextual local classification and authenticated browser/console handoff. Outlook prior-thread context remains unsupported.

- B's mascot/overlay, durable quarantine and passive Watchtower observations. Network observations do not imply full network enforcement.

- Installer with native Chrome connector registration, bundled extension and CPU model, Windows Hello startup prerequisite/instructions.

## Install

Download Sentinel-v3-Setup.exe and run it. Approximate download 1.3GB because the CPU model is bundled; allow at least 6GB free disk for extraction/staging. Windows x64, .NET Framework, WebView2 Runtime and configured Windows Hello are required. Installer extracts only manifest-verified bounded files and creates the desktop shortcut.

Chrome on unmanaged Windows requires one-time developer-mode approval for the bundled unpublished extension. Setup shows the folder and opens chrome://extensions. No silent Chrome-profile modifications. The extension is not published in the Chrome Web Store. The existing development machine's USB enrollment and protected worker are not copied to another PC; USB enforcement setup across arbitrary laptops is not qualified in this preview.

## USB limitations — read before enabling

Owner physically observed RP2040 Block success and receiver Block/Allow with reconnects, but earlier tests exposed keyboard/mouse recovery failures and an internal keyboard needed Windows restart even after policy release. The internal-keyboard cause remains unresolved. Therefore leave Guard off on everyday machines; this release does not guarantee safe universal internal-device exclusion, interception before first keystroke, immediate recovery, or restart persistence across arbitrary hardware.

Successful saved rules do not have a five-minute expiry; an unfinished transaction has bounded authenticated rollback. That crash-recovery safeguard remains. HID plus storage and reported model identifiers are clues, not proof of malicious hardware. Automatic BadUSB-profile-only denial is deferred to v3.5 and is not enabled here.
