## Design direction — Y2K Cyber Console

A maximalist shell around a precise, readable console. Deep navy background, azure #2f89e3 accent, chrome heading treatment, translucent layered navigation, restrained CRT grid/scanline touches, and technical monospace values. Use chrome effects for headings and framing, never small warning text. Dense reports, secrets, and warnings sit on readable opaque inner surfaces. Keep the console energetic and intentional without hiding its evidence.

The whole console breathes the threat state: shared border, glow, badge, ambient rhythm, and notification treatment derive from backend risk and capability data. Missing/stale/unavailable coverage is neutral/uncertain; complete checks with no finding do not mean universal safety. Show risk, coverage, freshness, and operating mode independently. Use text/icons as well as color. Critical warnings remain static and readable; no flashing. Stop ambient effects while hidden; provide reduced motion/transparency, forced-colors/high-contrast, and keyboard/screen-reader support. Main text at least 14 px; test worst-case translucent contrast, 200% scaling, and 400% reflow.

Implement design tokens and a small component system first, then shell/sidebar/status rail, dashboard, scan center, inspector/quarantine, USB, Wi-Fi, vault/password autopsy, browser surfaces, academy, activity, onboarding, and settings. Bring this visual identity into Phase 1-70 alongside functional delivery; R3 is final presentation/localization/accessibility regression closure, not the first opportunity to design. Avoid adding multiple animation/icon/UI libraries before their value and license are established.

## Essential journeys and state matrix

1. Dashboard: per-feature file/web/Wi-Fi/USB/vault state, live activity when connected, next useful action, separate learning progress. Explain missing service/host. Never show an invented aggregate protection percentage.
2. Scan: quick/full/custom/removable options with actual configured scope, cancel, genuine progress or indeterminate activity, counts of checked/skipped/errors, engine state, and detailed findings. Failed/cancelled/incomplete jobs cannot render clean. Fixtures are opt-in and permanently labeled. Use selected harmless local files only through authorized adapters.
3. Warning-to-awareness: notification click opens the assessment bound to that subject/time, with what was observed, why it matters, uncertainty, a safe next action, and an optional question panel. Use the same pattern for file, network, link, download, and password warnings. Deduplicate/rate-limit notifications; retain activity access and keyboard focus restoration.
4. USB: show storage/HID/other interfaces separately, actual hold/inspection/release state, report completeness and measured exposure gaps. No fake simulation/detonation stage, harmless-firmware certification, or automatic release after a green animation. Storage release never approves HID. Unsupported controls visibly remain unavailable; recovery is accessible independently.
5. Wi-Fi: plain-language evidence per check, timestamp and baseline comparison; explain public/open networks without declaring every public network malicious. Offer safer user actions with exact limitations. Charts have text/table alternatives. Unknown checks cannot increase a safety score.
6. Vault: desktop and extension share one backend vault; locked list/detail, unlock, audit, generator, backup/recovery, explicit reveal/copy/fill, and auto-lock feedback. Never keep plaintext in activity, analytics, debug dumps, screenshots, or AI prompts. Synthetic-only mode remains visible until reviewed. Explain import from user-selected exports and recommend disposing of exported plaintext without deleting it silently.
7. Password autopsy: explain length, reuse/common patterns, and breach result without revealing the password. Crack-time displays are illustrative ranges with an attacker-model assumption, never guaranteed years. Generator/copy and navigation to the official account settings help the user change a password; do not promise automatic account changes. AI uses sanitized reasons, not masked plaintext sent behind the scenes.
8. Browser: accessible popup, local block page, narrow temporary override, source-risk versus completed file inspection, native-host absent/disconnected states, opt-in mail/WhatsApp Web warnings and paused/partial adapter states. Page content cannot trigger arbitrary privileged desktop actions. Content banners must not alter host CSS or steal essential focus.
9. Academy/activity/settings: all 25 lessons by R2, voluntary practice and progress separate from machine protection; unified bounded redacted event history; provider consent, retention, motion/transparency, languages, diagnostics, and honest about/version information.

Every meaningful screen handles empty, loading, connected, fixture, unavailable, offline, stale, partial, failed, cancelled, and disabled states where applicable. Use localization keys and logical layout properties immediately; Arabic RTL/Hindi/Malayalam reviewed translations arrive at R3. No operational button may silently do nothing: connect it to an authorized real action, or disable it with an explanation and tracked dependency.
